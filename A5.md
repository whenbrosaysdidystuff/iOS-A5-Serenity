# ios-serenity: ios-sweet on the Redmi A5 (serenity, Unisoc UMS9230)

Branch `a5`. Hardware facts come from the a5-ios-port probes (all measured on the phone):
EL2 entry, GICv3 `0x10000000`/`0x10040000`, virtual timer INTID 27 at 26 MHz, PSCI over SMC
(secondaries also start at EL2), framebuffer 720x1640 at `0x9cf2a000`, eMMC SDHCI v4 at
`0x201d0000` (32-bit block-size writes only, always DMA), RAM `0x80000000`+3 GiB with the
largest free block from `0xb6100000`.

## What differs from sweet
| Piece | A5 |
|---|---|
| `shim-a5/` | Boot shim: drops EL2 -> EL1, payload **appended to the shim Image** (the A5's U-Boot takes its ramdisk from init_boot/vendor_boot and refuses `fastboot boot`), built with clang/lld |
| `tools/mka5boot.py` | shim + payload -> boot.img v4 for `boot_b` |
| `tools/mkadt.py --a5` | A5 memory/GIC/timer/framebuffer; no UFS / AppleCLCD nodes yet |
| `xnu/patches/0082-a5-early-framebuffer.patch` | early console on the A5's 720x1640 framebuffer (same 32 MB mapping block as sweet) |

## Build and boot (first bring-up)
```
gh workflow run xnu.yml -R yeah6Nine/ios-serenity --ref a5
gh run download RUN_ID -R yeah6Nine/ios-serenity -n xnu-kernel -D xnu/out
python3 tools/mkadt.py shim-a5/out/a5.adt --a5
python3 tools/mkpayload.py xnu/out/kernel.development.sweet shim-a5/out/a5.adt shim-a5/out/payload.bin \
    --cmdline 'debug=0xc serial=3 cpus=1 keepsyms=1 -enable_kprintf_spam -noprogress rd=md0 sweetkeys=0 sweettouch=0 sweetusb=0 sweetlog=0 wdt=-1 wdt_test=no_user_checkin'
shim-a5/build.sh out/payload.bin          # -> shim-a5/out/a5-boot.img
fastboot flash boot_b shim-a5/out/a5-boot.img && fastboot set_active b && fastboot reboot
```
`cpus=1` until xnu's PSCI entry learns the EL2 -> EL1 drop; the sweet-only drivers (keys, touch,
USB, UFS log) are switched off by boot-arg because they poke Qualcomm addresses.
